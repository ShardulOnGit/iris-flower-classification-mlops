---

## 📌 Project Overview

- **Problem Statement:** Build a machine learning system that identifies the species of an Iris flower using its sepal and petal measurements.
- **Input Features (cm):**
  1. `sepal_length` (float)
  2. `sepal_width` (float)
  3. `petal_length` (float)
  4. `petal_width` (float)
- **Output:** One of three species: **Setosa**, **Versicolor**, or **Virginica** (with class probabilities & confidence score).
- **ML Algorithm:** Random Forest Classifier (`sklearn.ensemble.RandomForestClassifier`).
- **Dataset:** Scikit-learn Iris dataset (150 observations: 50 for each of the three classes; no external download required).

## 🛠️ Integrated MLOps Toolchain

| Tool | Role & Implementation |
| :--- | :--- |
| **Git** | Distributed source code versioning, branch management, and tracking of pipeline definitions. |
| **DVC (Data Version Control)** | Reproducible, version-controlled multi-stage data & model pipeline (`load_data` -> `preprocess` -> `train` -> `evaluate`). |
| **Scikit-learn** | Built-in dataset ingestion, stratified train/test splitting, Random Forest training, and multi-class classification metrics. |
| **MLflow** | Experiment tracking, hyperparameter logging, model artifact registration, and metrics visualization via SQLite store (`sqlite:///mlflow.db`). |
| **Pytest** | Automated unit & integration tests covering data integrity, model performance benchmarks (accuracy ≥ 0.90), and API endpoints. |
| **GitHub Actions** | Automated CI/CD pipeline on push/PR (`.github/workflows/ci-cd.yml`) executing linting, test suites, DVC pipeline validation, and Docker builds. |
| **FastAPI** | High-performance asynchronous RESTful API with Pydantic request/response validation, OpenAPI/Swagger docs, `/health`, `/model-info`, and batch inference. |
| **Docker & Compose** | Containerized microservice with non-root security privileges, health check probes, and `docker-compose.yml` for unified API and MLflow UI deployment. |

## ⚡ Quick Start

### 1. Prerequisites
- Python 3.10 or 3.11
- Git
- Docker (optional, for containerized execution)

### 2. Virtual Environment Setup
```bash
# Clone the repository
git clone <repository_url>
cd MLOPS

# Create virtual environment
python -m venv .venv

# Activate on Windows:
.venv\Scripts\activate
# Activate on Linux / macOS:
# source .venv/bin/activate
```

## 🔄 Reproducible Data & Model Pipeline with DVC

The entire lifecycle (data ingestion, validation, preprocessing, model training, evaluation) is encoded as a DVC Directed Acyclic Graph (DAG) in `dvc.yaml`:

```mermaid
flowchart LR
    A[load_data] --> B[preprocess]
    B --> C[train]
    C --> D[evaluate]
```

### Reproduce the Full Pipeline:
```bash
dvc repro
```

### View Pipeline Metrics:
```bash
dvc metrics show
```
Output:
```json
{
  "accuracy": 0.9667,
  "f1_weighted": 0.9666,
  "precision_weighted": 0.9697,
  "recall_weighted": 0.9667
}
```

### View Confusion Matrix Plot:
```bash
dvc plots show metrics/confusion_matrix.png
```

## 📈 Experiment Tracking with MLflow

MLflow tracks all hyperparameters, model versions, and evaluation metrics:
- **Tracked Parameters:** `n_estimators`, `max_depth`, `min_samples_split`, `criterion`, `random_state`, `features`, `n_train_samples`.
- **Tracked Metrics:** `train_accuracy`, `test_accuracy`, `test_precision`, `test_recall`, `test_f1`.
- **Logged Artifacts:** Model package, confusion matrix image, classification metrics JSON.

### Launch the MLflow UI:
```bash
mlflow ui --backend-store-uri sqlite:///mlflow.db --port 5000
```
Open **`http://localhost:5000`** in your browser to view experiment runs, compare runs, and inspect model artifacts.

## 🧪 Automated Testing with Pytest

Run the comprehensive test suite (18 unit & integration tests):
```bash
pytest -v
```

Test coverage includes:
- **Data integrity:** Verification of 150 rows, 50 samples per class, non-null values, positive bounds.
- **Preprocessing:** Stratified train/test partition preservation (120 train / 30 test).
- **Model quality:** Verifying accuracy exceeds production benchmark threshold (≥ 90%).
- **Inference logic:** Verification of class mappings and probability distributions.
- **API validation:** Verification of HTTP 200 responses, 422 input validation errors, and batch predictions.

## 🚀 Serving the REST API with FastAPI

### Start the API Locally:
```bash
uvicorn src.api.main:app --host 0.0.0.0 --port 8000 --reload
```

Interactive API documentation (Swagger UI) is available at:
👉 **`http://localhost:8000/docs`**

### Available Endpoints:
- `GET /`: Service welcome message and documentation link.
- `GET /health`: Health status probe and model availability check.
- `GET /model-info`: Inspect active model metadata, features, and classes.
- `POST /predict`: Predict flower species for a single observation.
- `POST /predict/batch`: Predict flower species for multiple observations.

### Example Single Prediction Request:
```bash
curl -X POST "http://localhost:8000/predict" \
     -H "Content-Type: application/json" \
     -d '{
       "sepal_length": 5.1,
       "sepal_width": 3.5,
       "petal_length": 1.4,
       "petal_width": 0.2
     }'
```

**Response:**
```json
{
  "predicted_class_id": 0,
  "predicted_species": "Setosa",
  "confidence": 1.0,
  "probabilities": {
    "Setosa": 1.0,
    "Versicolor": 0.0,
    "Virginica": 0.0
  }
}
```

### Example Batch Prediction Request:
```bash
curl -X POST "http://localhost:8000/predict/batch" \
     -H "Content-Type: application/json" \
     -d '{
       "flowers": [
         {"sepal_length": 5.1, "sepal_width": 3.5, "petal_length": 1.4, "petal_width": 0.2},
         {"sepal_length": 6.0, "sepal_width": 2.9, "petal_length": 4.5, "petal_width": 1.5},
         {"sepal_length": 6.9, "sepal_width": 3.1, "petal_length": 5.4, "petal_width": 2.1}
       ]
     }'
```

## 🔁 CI/CD Workflow (GitHub Actions)

The repository includes a ready-to-use GitHub Actions workflow (`.github/workflows/ci-cd.yml`):
1. **Lint & Test:** Runs Python 3.11 setup, dependencies installation, and `pytest`.
2. **Pipeline Check:** Verifies `dvc repro --dry` to ensure reproducibility.
3. **Container Build & Test:** Builds the Docker image, starts the container, and triggers the `/health` endpoint probe.
